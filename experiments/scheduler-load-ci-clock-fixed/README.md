本目录绑定提交 `8dff3533cc152f00e09cce8192737ae7e10d961f`。实际六个 job 日志均核对了 checkout SHA；两份原始 ZIP 的字节数和 SHA-256 均与 GitHub artifact 元数据一致。原报告与逐项回读未改写。[完整收据](validation.json)

Windows 在 `full_readback` 阶段失败。`load-000388`、`load-000528`、`load-000563` 的 generation 1 分别经过约 5.047、5.020、5.025 秒后记为 `lease_expired`，随后 generation 2 成功。原严格验收要求普通任务只有一次成功尝试，因此拒绝这三条；另一个条件要求 1000 条 worker 成功确认，本次只收到 999 条。故障注入中的 worker 强杀重派、旧租约拒绝、取消、协调器重启均通过，但不能据此把整个 Windows 负载改为通过。

现存报告没有逐项 worker HTTP/提交回执，无法确定哪一个请求造成缺失确认，也不能从租约历史直接推断是心跳逻辑、响应延迟、锁等待还是其他资源竞争。安全回读和数据库审计证明本次所有任务最终存在且没有重复接受；它们不等于 worker 全部收到了确认。原始失败保持不变。

后续可使用显式的 30 秒负载租约配置验证调度余量，仍要求 1000 个任务、8 个进程、单次尝试和全部确认；这样的新结果不能证明本次 5 秒配置稳健。5 秒跨初始租约的 gated 心跳协议测试属于普通测试套件中的另一项验证。
